Denna sida innehåller en lista över de FHIR-artefakter som definieras som en del av denna implementationsguide.

Krav: Aktörsdefinitioner

Följande artefakter definierar de typer av individer och/eller system som kommer att interagera som en del av de användningsfall som täcks av denna implementationsguide.

Synkroniseringstjänst

Aktör: System som läser organisationer och ändpunkter från tjänstekatalogens administrativa API och håller E-hälsomyndighetens nationella register synkroniserat genom att, i deras system, anta rollen Organization Endpoint Writer.

Krav: Formella krav

Följande artefakter beskriver de specifika krav som ska uppfyllas av system som följer implementationsguiden.

Kravkatalog: Tjänstekatalogen

Formell kravkatalog för tjänstekatalogen, med spårning från krav till realiserande FHIR-artefakter.

Beteende: Förmågedeklarationer

Följande artefakter definierar de specifika förmågor som olika typer av system förväntas ha för att följa denna implementationsguide. System som följer denna implementationsguide förväntas deklarera överensstämmelse med en eller flera av följande förmågedeklarationer.

Tjänstekatalogen: administrativt API

CapabilityStatement för tjänstekatalogens administrativa API (serverroll).
Tjänstekatalogen: sök-API (externt)

CapabilityStatement för tjänstekatalogens externt exponerade sök-API (serverroll), nått via gateway.

Beteende: Sökparametrar

Dessa definierar de egenskaper som en RESTful-server kan sökas på. De kan också användas för sortering och inkludering av relaterade resurser.

CapabilityStatement: instantiates

Söker fram de TKAPIInstance-resurser som följer en angiven API-specifikation (CapabilityStatement.instantiates). Se REQ-MDL-7.
CapabilityStatement: kind

Söker CapabilityStatement-resurser efter kind (requirements = API-specifikation, instance = API-instans). Se REQ-MDL-4.
Endpoint: implements (stödd interoperabilitetsspecifikation)

Söker fram de Endpoint-resurser vars nyttolast (Endpoint.payload) stödjer en angiven interoperabilitetsspecifikation, dvs. vars TKEndpointPayloadProfile-extension namner den angivna kanoniska URL:en. Se REQ-SRCH-4.
Endpoint: listed-by (organisation som listar ändpunkten)

Söker fram de Endpoint-resurser som en angiven Organization listar i sin ändpunktskatalog, dvs. de ändpunkter som förekommer i Organization.endpoint ("har"-relationen i informationsunderlaget) — till skillnad från standardparametern organization, som endast matchar den förvaltande organisationen (Endpoint.managingOrganization, "förvaltar"-relationen). Servrar SKA implementera denna parameter med sökbeteende likvärdigt med _has:Organization:endpoint:_id=[organization-id].

Beteende: Prenumerationsämnen

Dessa definierar de typer av information som kan prenumereras på i system som följer denna implementationsguide.

Ändringar i Organisation/Ändpunkt (prenumerationsämne)

SubscriptionTopic för händelsebaserad distribution av förändringar i Organization/Endpoint till lokala kataloger. Se REQ-DIST-1.

Strukturer: Logiska modeller

Dessa definierar datamodeller som representerar den domän som täcks av denna implementationsguide i mer verksamhetsvänliga termer än de underliggande FHIR-resurserna.

Indexpost (logisk modell)

Logisk modell för entiteten Indexpost i informationsunderlaget. Ej REST-exponerad i detta utkast av det administrativa API:et — se REQ-MDL-1.
Vård- och omsorgstagare (logisk modell)

Strukturer: Resursprofiler

Dessa definierar begränsningar på FHIR-resurser för system som följer denna implementationsguide.

Inera Patient

A template patient profile demonstrating Inera's FHIR profiling conventions. Authors should replace this description with the clinical purpose and scope of the profile.
Tjänstekatalogen API-instans

Ett API som en teknisk ändpunkt tillgängliggör ("tillgängliggör"), och den eller de interoperabilitetsspecifikationer det följer ("följer"), som en egen resurs med egen identitet och egen giltighetsperiod — se Kravkatalog REQ-MDL-3, REQ-MDL-6, REQ-MDL-7.
Tjänstekatalogen API-specifikation

Metadata om en interoperabilitetsspecifikation (t.ex. en FHIR IG, ett RIVTA-tjänstekontrakt eller en OpenAPI/REST-beskrivning) som en TKAPIInstance kan referera via .instantiates ("följer"). CapabilityStatement.url är specifikationens egen kanoniska/maskinläsbara identitet — samma värde som TKEndpointPayloadProfile på Endpoint.payload refererar för snabb sökbarhet. Se Kravkatalog REQ-MDL-4.
Tjänstekatalogen Endpoint

Teknisk ändpunkt i tjänstekatalogen. Realiserar entiteten Ändpunkt i det bifogade informationsunderlaget: Endpoint.address bär ändpunktens URL, Endpoint.managingOrganization bär "förvaltar"-relationen till den förvaltande organisationen, och Endpoint.payload (tillsammans med TKEndpointPayloadProfile) bär "tillgängliggör"/"följer"-relationerna till de API:er och interoperabilitetsspecifikationer som ändpunkten stödjer. Sök efter ändpunkter som en organisation listar (Organization.endpoint, "har") med SearchParameter: listed-by; sök efter ändpunkter en organisation förvaltar med standardparametern organization.
Tjänstekatalogen Organization

Organisation i tjänstekatalogen. Organization.endpoint bär "har"-relationen — de ändpunkter organisationen listar i sin katalogpost, oavsett vem som förvaltar dem tekniskt. Sök efter dessa ändpunkter med SearchParameter: listed-by på Endpoint, med organisationens id/referens som värde. Den separata "förvaltar"-relationen (vem som tekniskt driftar en given ändpunkt) uttrycks istället av TKEndpoints managingOrganization, sökbar med standardparametern organization.
Tjänstekatalogen Provenance

Spårbarhetspost för en registrering (skapande/uppdatering) av en eller flera resurser i tjänstekatalogen — vanligen skickad tillsammans med den/de registrerade resurserna i samma transaction-Bundle. Se Kravkatalog REQ-TRC-1/2 och "Distribution och synkronisering"/registrering i rest-interactions.html.
Tjänstekatalogen administratörsbehörighet

Behörighet för en administratör att registrera/ändra poster i tjänstekatalogen för en given organisation (local-admin), eller att dessutom administrera andra administratörers behörigheter för samtliga organisationer (central-admin, organization utelämnad). Se Roller och ansvar och Kravkatalog REQ-ADM-*.

Strukturer: Extensiondefinitioner

Dessa definierar begränsningar på FHIR-datatyper för system som följer denna implementationsguide.

API-instansens giltighetsperiod

API-instansens (TKAPIInstance) egen giltighetsperiod, oberoende av den ändpunkt som tillgängliggör den (API.giltigFrom/giltigTom i informationsunderlaget).
Ansvarig organisation (strukturerad referens)

Strukturerad referens till organisationen som ansvarar för en TKAPISpecificationCapability (API-specifikation.ansvarigUtgivare i informationsunderlaget). Komplement till CapabilityStatement.publisher (string).
Referens till källa

Länk till specifikationens källa/publiceringsplats (t.ex. dokumentation eller repository), skild från den kanoniska maskinidentiteten CapabilityStatement.url (API-specifikation.referensTillKälla i informationsunderlaget).
Specifikationskategori

Typ av specifikation, t.ex. FHIR, REST/OpenAPI, SOAP/RIVTA-tjänstekontrakt (API-specifikation.kategori i informationsunderlaget). Basresursen CapabilityStatement saknar ett eget element för klassificering av detta slag.
Stödd specifikation (payload profile)

Kanonisk URL för en interoperabilitetsspecifikation (t.ex. en FHIR IG eller profil) som denna nyttolast/API stödjer. Motsvarar det kommande elementet Endpoint.payload.profile. Kan upprepas om nyttolasten stödjer flera specifikationer eller versioner.
Säkerhetsmetod

Anger vilken säkerhetsmetod som skyddar åtkomst till ändpunkten (Ändpunkt.säkerhetsmetod i informationsunderlaget). Basresursen Endpoint saknar ett eget element för detta i R5.
Tillgängliggörande ändpunkt

Den ändpunkt (TKEndpoint) som tillgängliggör denna API-instans ("tillgängliggör"). Basresursen CapabilityStatement har inget element för detta.
URL till auktorisationsserver

URL till den auktorisationsserver (t.ex. OAuth 2.0-token-endpoint) som klienter ska använda för att erhålla åtkomst till ändpunkten (Ändpunkt.urlTillAuktorisationsserver i informationsunderlaget). Relevant framför allt när Ändpunkt.säkerhetsmetod anger en OAuth 2.0-baserad metod.
